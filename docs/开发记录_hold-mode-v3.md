## 2. 主要设计决策及理由

### 2.1 只留张力保持(HOLD),废除 PUMP

延べ竿没有卷线器,泵竿是卷线器钓法的技术——旧 PUMP 模式其实是移植错位的
卷线小游戏。张力保持(ため)才是这根竿真实的搏鱼方式,而且它提供了
**稳定持续的刺激呈现窗口**,这是做尺寸感知测量的前提。
"拉紧才有振动、放松就没"同时是物理诚实(振动经绷紧的线传导)和
文献支持(动作随伴性、line-slack 线索)的交点。

### 2.2 尺寸=固定二水准,不再随机抽签

感知实验要求刺激可复现。SML=0.20 / BIG=0.85(串口 `fs`/`fb` 可调),
三条冗余通道编码:振幅(比 1.75)、基频(约 41Hz vs 32Hz,低频=重)、
段完成瞬态余振(τ 70ms vs 135ms)。方向全部对齐"大=强・慢・沉",
与钓鱼实践的经验则(ブルブル=小物/ドンドン=大物)一致。

### 2.3 结构同一 + 盲测:堵死非触觉线索

两条件的段数/段长/失败规则/音效完全一致(否则"打得久=大鱼"会淹没触觉
通道);`bl 1` 隐藏屏幕所有尺寸线索,连 BtnB 切换音都统一。串口日志
`cond=BIG size=0.85 ...` 是实验者的正解记录。

### 2.4 对比度"向下让"而非"向上顶"

供电限幅(§3)压住输出上限后,发现旧映射下两条件的突进段都被钳平成同感。
关键洞察(用户提出):**尺寸弁別是相对判断**——把 SML 往下让(振幅下限
0.55→0.40、频率上探贴共振点),在供电预算内反而拉宽了对比,还白赚共振区
的机械效率补偿。BIG 参数一个没动。

## 3. 最大的困难:BIG 条件 brownout 侦破记

**现象**:大鱼条件战斗中屏幕熄灭、整机重启,小鱼从不发生。

侦破过程走了四步,每一步都修正了上一步的错误假设:

1. **假设"振幅太大"→ 加基线限幅 `pl 0.75`**——仍然崩。
2. **抓串口日志**:发现板子撑过了 3.2 秒持续振动、恰好死在
   `SEGMENT 1/4 done` 的瞬间——真凶是段完成时叠加的**满幅瞬态敲击**
   (tap 1.0 叠在基线上顶到满摆幅),基线限幅根本管不到它。
   → 限幅移到 haptics 混音后最终钳制(基线+敲击+泄力 click 合算后)。
3. **仍崩,且串口抓取屡屡错过关键瞬间**(监视器重连竞速、PC USB 口本身
   是最弱供电,测试环境失真)→ **把诊断仪器化**:开机读
   `esp_reset_reason()` 显示在待机画面(`rst:BROWNOUT` 红字),
   从此脱离电脑即可确诊。充电宝供电下复现红字 → 供电垂下实锤。
4. **查参数定根因**:充电宝额定 5V/2.1A 足够平均电流(~0.3A),垮在
   **瞬态**——5ms 类方波脉冲的电流阶跃(满幅峰值 ≈1A)快于
   "充电宝稳压环路+线阻+M5 内部供电路(M5PM1)"的响应;M5 官方文档
   佐证(电池供电下内置扬声器 75% 音量即可重启)。BIG 独中三重叠加:
   振幅顶格 × 29Hz 低于共振点(阻抗最小、电流最大)× 3.2s 连续。

**落地对策**:软件侧 `pl` 默认 0.60 + 战斗中背光降 170 + 对比度下移
(§2.4),当前稳定可用;硬件侧三方案已设计待实施(VIN 并 1000µF 电容/
功放独立 5V/GAIN→VIN 降 6dB),完成后 `pl 1` 恢复满幅。
详见 `changes/2026-08-26-brownout供电对策记录.md`。

**教训**:①限幅要在信号链**最末端**做,中途任何一层都可能被后续叠加绕过;
②抓不到的现场就把仪器造进设备里(屏显复位原因一劳永逸);
③在最弱供电(PC USB)上调试供电问题,环境本身就是混杂变量。

## 4. 其他困难与解法

| 困难 | 根因 | 解法 |
|------|------|------|
| 2号机首次烧录 Write timeout,重试无效 | 新板 USB CDC 卡死 | 按住 BtnA(G0)插 USB 进 ROM 下载模式(PID 变 1001),烧后恢复。已记入烧录笔记 |
| 待机连续底流"一直微微震,很奇怪" | 28Hz 保活音略高于体感阈 | 整体重做:45s 渚涌浪+连续底流 → **25s 心跳双跳**(lub-dub,低振幅),保活由心跳兼任;底流合成保留 `wk` 可复活 |
| 「走らせる」机制加重 brownout | 突进段无论让竿与否都持续满预算输出(旧行为里让竿=静音,供电轨得以喘息) | 整体 revert,代码留在历史(`c1ea14d`),硬件对策后可复活 |
| 文献署名错误 | 代码注释写"Tanaka ら 2020(40Hz)" | 查证实为 **Tanabe(田辺健,AIST)ら**, Sensors 20(24), 2020;报告文档已用正确署名 |
| 串口后台抓日志不可靠 | Python stdout 缓冲+监视器重连竞速+会话中断 | 放弃依赖串口诊断,改屏显 rst(见 §3) |

## 5. 具体改动清单(相对 main 分支)

**src/main.cpp**
- 删除:PUMP 模式全部(泵竿检测/甜区光标/运动耦合 `mc`/相关常量变量)
- 战斗:HOLD 唯一玩法;泄力打滑区(48–55°)、段完成尺寸化瞬态
- 尺寸:`sizeMode` 二水准(`fm`/`fs`/`fb`)、结构同一(`dc`)、盲测(`bl`)
- 供电:`pl` 峰值限幅(默认 0.60)、`BRIGHT_FIGHT` 战斗减光、
  `rst:` 复位原因屏显
- 待机:IDLE/CAUGHT/FAILED 进入 HAPTIC_WAVE(心跳)

**src/haptics.cpp/h**
- PULL 新增:引き込み节律(`hapticSetTug`,抗适应)、泄力打滑 click 列
  (`hapticSetSlip`)、混音后峰值钳制(`hapticSetPullLimit`)
- `hapticTriggerTap` 增加可选余振 τ 参数(尺寸化瞬态用)
- WAVE 波形:渚涌浪 → 心跳双跳;底流默认 0

**串口命令变化**:新增 `pl` `fs` `fb` `bl` `dc` `ht` `hf` `hd`;
`fm` 语义从"玩法切换"变为"大小条件";删除 `mc`。

**docs/**:先行研究_HOLD模式(文献调研)、brownout 对策记录、
装置说明通俗版、各 change 文档,PROJECT_LOG/HAPTICS_GUIDE 同步更新。
